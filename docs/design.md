# 設計と機器選定

## 1. 目的と方針

- 外国語の患者さんには **翻訳して**、耳の不自由な患者さんには **日本語のまま**、医師の話した内容を患者さんの手元に文字で出す。
- **誤認識・誤訳を患者さんに見せない**。リアルタイム字幕にはせず、必ず医師が確認してから送る。
- 翻訳は **逆翻訳（訳文を日本語に戻したもの）** で医師が意味を確認する。
- すべての操作を **ログ** に残す。
- 将来は PC の拡張ディスプレイを使わず、**USB / Bluetooth で文字だけを送る小型端末（電子ペーパー）** に表示する。
- 文字はできるだけ大きく。

## 2. 処理の流れ

```
 医師PC                                                        患者の手元
┌────────────────────────────────────────────────────┐
│ ① 録音（ボタン or F8 / フットスイッチ）            │
│      ↓ 音声はPC内で処理（faster-whisper）          │
│ ② 認識結果を下書きとして表示 → 医師が修正・確定    │
│      ↓（筆談モードなら ④ へ）                      │
│ ③ 翻訳（Gemini API。Claude API にも切替可）        │
│    → 訳文を「別の会話で」日本語に直訳して表示      │
│    → 医師が意味を確認（訳文を直したら再確認）      │
│ ④ プレビュー（患者側と同じ画像）→「患者に送る」   │ ──USB/BLE──▶ 電子ペーパー
│                                                    │ ──Wi-Fi───▶ タブレットのブラウザ
│ ⑤ 患者の返答「わかりました/もう一度/質問がある」 │ ◀─タッチ──
└────────────────────────────────────────────────────┘
          全イベントを logs/YYYY-MM-DD.jsonl に記録
```

### 「確認していないものは出さない」の担保

画面の作りだけに頼らず、サーバー側でも送信時に検査しています（`app/server.py` の `send`）。

| 状況 | 結果 |
|---|---|
| 翻訳モードで、まだ翻訳・逆翻訳していない | 送信拒否 |
| 逆翻訳で確認した後に、訳文が書き換えられた | 送信拒否（もう一度逆翻訳が必要） |
| 翻訳した後に、元の日本語が書き換えられた | 送信拒否（翻訳し直しが必要） |
| 言語を切り替えた | それまでの確認は無効 |
| 音声認識の結果 | 常に「下書き」。患者側には一切流れない |

### 逆翻訳を「別の会話」で行う理由

同じ会話の中で「今の訳を日本語に戻して」と頼むと、AI は元の日本語を覚えているため、
訳文が間違っていても正しい日本語を返してしまい、確認になりません。
そこで逆翻訳は元の日本語を一切渡さず、訳文だけを渡して「整えずに直訳」させています。

## 3. ソフトウェア構成

| 部分 | 採用 | 理由 |
|---|---|---|
| 医師用画面 | ブラウザ（PC内のローカルWebサーバー） | インストール不要。Windows / Mac 共通 |
| サーバー | Python 3.12 + FastAPI | 既存環境（Python）で完結。ライブラリが豊富 |
| 音声認識 | faster-whisper（Whisper large-v3-turbo） | **PC内で処理し音声を外部に出さない**。日本語精度が高い。GPUがあれば1〜2秒 |
| 翻訳 | Gemini API（`gemini-3.8-flash`）。設定で Claude API に切替可 | 医療文脈の正確さ、平易な言い換え、数値・薬名の保持を指示できる |
| 患者側描画 | PC側で Pillow により白黒画像化 | 端末にフォント不要。タイ語・ネパール語なども PC のフォントで対応 |
| ログ | JSON Lines（1日1ファイル）＋ CSV 出力 | 追記のみで壊れにくい。CSVは Excel / SmoothCSV で開ける |

### 個人情報について

- 音声はPC内で文字にして、既定では保存しません（`save_audio`）。
- 翻訳時は **日本語の文章だけ** が翻訳 API（Gemini または Claude）に送られます。患者の氏名などは入れない運用にしてください（受付番号欄も番号だけを推奨）。
- 医療機関で使う前に、「医療情報システムの安全管理に関するガイドライン」や院内の規程に照らして、外部サービスの利用可否を確認してください。Gemini API は **無料枠だと送信内容が Google の製品改善に使われる** ことがあるため、必ず請求設定をした有料枠で使ってください（有料枠と Claude API の商用規約では、既定で学習に使われません）。より厳しい条件が必要なら、ゼロデータ保持の契約を結ぶか、翻訳を院内で動くモデルに差し替えます（`translator.py` を差し替える形にしてあります）。
- 患者さんには「機械翻訳を使っています」と伝え、重要な説明（同意書、手術、服薬の重大な注意）は医療通訳や書面の翻訳を併用してください。本システムは医療機器ではなく、意思疎通の補助です。

## 4. 機器選定

### 4.1 患者側の表示端末

| 候補 | 画面 | 接続 | 価格の目安（購入前に要確認） | 評価 |
|---|---|---|---|---|
| **M5PaperS3**（M5Stack） | 4.7インチ 電子ペーパー 960×540、タッチ | USB-C（シリアル）、BLE、Wi-Fi | 1.2万円前後 | **第1候補（実装済み）**。ケース・電池・タッチ込みで完成品。消費電力が小さく、表示し続けても電池が減らない |
| LILYGO T5 4.7" S3 | 4.7インチ 960×540 | USB-C、BLE | 7千〜9千円 | 安いがケースが別。基板むき出しなので診察室向きではない |
| Seeed reTerminal E シリーズ | 7.3〜7.5インチ 電子ペーパー | USB-C、BLE、Wi-Fi | 1.5万〜2.5万円 | 文字を大きくしたい場合の次の候補。ESP32-S3搭載で同じ方式が使える（画面サイズの設定変更とファーム移植が必要。タッチなし→返答ボタンは物理ボタンで） |
| 電子ペーパー Android（BOOX など） | 7.8〜10.3インチ | Wi-Fi（ブラウザ） | 4万〜8万円 | **改造なしで今すぐ使える大画面**。`/patient` をブラウザで開くだけ |
| 安価な Android タブレット | 8〜10インチ 液晶 | Wi-Fi（ブラウザ） | 1.5万〜3万円 | 最も手軽。拡張ディスプレイ端子は消費しない |

**おすすめの進め方**

1. **すぐ試す**: 手持ちのタブレットやスマホで `http://<PCのIP>:8000/patient` を開く（Wi-Fi、ディスプレイ端子不要）。
2. **本番**: M5PaperS3 を USB で接続（`firmware/m5papers3`）。USB は給電も兼ねるので電池切れの心配がなく、ペアリングも不要で、診察室では Bluetooth より確実です。
3. **文字をもっと大きく**: 4.7インチで足りなければ 7.5インチ級（reTerminal E 等）へ。PC側で画像を作る方式なので、`display_width/height` を変えてファームを移植するだけで済みます。

4.7インチ 960×540 での文字サイズの目安: 最大 96px ≒ 1文字 約10mm角。短い文なら 2〜3 行、長い文でも最小 36px（約4mm）で 8 行程度。収まらない場合は医師側の画面に「分けて送ってください」と警告が出ます。

### 4.2 Bluetooth にする場合（第2段階）

- 送るデータは同じフレーム形式（`app/serial_display.py` 参照）を BLE の Write で分割送信する予定です。
- 1枚 64.8KB（960×540 の 1bit 画像）。BLE では実効 20〜50KB/s 程度なので 2〜3 秒かかります。白黒の文字画像はよく圧縮できるので、圧縮（zlib または単純なランレングス）を入れて 1 秒以内を目標にします。
- PC側は Python の `bleak`、端末側は NimBLE で実装予定。院内の他の Bluetooth 機器との干渉・ペアリング管理の手間があるため、**まずは USB を推奨** します。

### 4.3 医師側のマイク

| 用途 | おすすめ | 理由 |
|---|---|---|
| 基本 | 卓上のUSBグースネックマイク（単一指向性） | 患者さんや周囲の声を拾いにくい |
| 動き回る・マスク越し | ワイヤレスのピンマイク（USB受信機タイプ） | 口元で拾うので認識精度が安定する |
| 手がふさがる | **USBフットスイッチ**（キー割り当て可能なもの） | 踏んでいる間だけ録音（F8 を割り当て）。診察中に手を使わずに済む |

ノートPC内蔵マイクは雑音を拾いやすく、誤認識が増えるので避けてください。

### 4.4 PC

- 音声認識を速くするなら NVIDIA GPU（VRAM 6GB 以上）付きの Windows PC が最適（large-v3-turbo で 1〜2 秒）。
- GPU がない場合は `asr_model` を `small` か `medium` に（数秒〜十数秒）。Apple シリコンの Mac は CPU 動作でも比較的速いです。

## 5. 今後の拡張案

- BLE 接続（4.2）
- 患者さんが返答ボタンを押したとき端末側でも押した印を出す
- 定型文の訳を事前に確認・登録しておき、確認済み訳として即送信できるようにする
- 聴覚障害の方向けに「やさしい日本語」への言い換えオプション
- 患者さんからの文字入力（手書き・キーボード）を医師側に表示・翻訳
